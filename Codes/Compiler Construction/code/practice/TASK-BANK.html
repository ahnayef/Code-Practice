Compiler Construction Lab — Task Bank

136 self-contained tasks. Each task stands alone: it states the full rules, gives its own sample input and its own exact expected output. No task refers to another task, to a file, or to a previous answer. Solve them in any order.

Conventions used by every task

  • Write a single flex program (.l) unless the task says plain C.
  • Input arrives on stdin unless the task says file.
  • Build: flex task.l && gcc lex.yy.c -lm -o task
  • <BLANK> in an expected output means an empty line. <TAB> means a tab character.
  • Sample inputs are tiny on purpose, so the expected output can be checked character by character.

Difficulty ★ 15 min · ★★ 25 min · ★★★ 40 min · ★★★★ 60 min (a small project).

A · Reading input and reporting

A1 · Words and numbers ★ Read a stream of words and integers. For each token print <word>: word or <number>: integer, one per line, in input order. Any other character is ignored.

IN   alpha 42 beta 7
OUT  alpha: word
     42: integer
     beta: word
     7: integer

A2 · Read from a file, handle the missing case ★ Read input.txt. For every word print WORD <text>; for every integer print NUM <n>. If the file does not exist print exactly File not found! and stop. Nothing else may be printed.

IN   (input.txt contains) one 2 three
OUT  WORD one
     NUM 2
     WORD three

A3 · Everything on one line ★ Print every word and every integer separated by a single space, without a trailing space, then a newline, then count <n> where <n> is the number of tokens printed.

IN   ab 12 cd
OUT  ab 12 cd
     count 3

A4 · Token lengths ★ For each maximal run of letters and each maximal run of digits, print <token>(<length>) with no spaces between them. Newlines are ignored.

IN   int xy 12345
OUT  int(3)xy(2)12345(5)

A5 · Stop at a sentinel ★★ Scan until the word stop appears as a complete word. Print token <text> for every word and number seen before it, then stopped after <n> tokens. Everything after stop must produce no output at all.

IN   a 1 b stop c 2
OUT  token a
     token 1
     token b
     stopped after 3 tokens

A6 · One word per line, with its position ★ The input has exactly one word per line. Print <line number>. <word> (<length>). Line numbers start at 1.

IN   cat
     elephant
OUT  1. cat (3)
     2. elephant (8)

A7 · Echo with markers for unprintable characters ★★ Copy the input to the output, but replace every TAB with <TAB> and every newline with <NL> immediately followed by a real newline. All other characters are copied unchanged.

IN   a<TAB>b
     c
OUT  a<TAB>b<NL>
     c<NL>

A8 · Count only, report at the end ★ Read the whole input silently and print at the end four lines: letters <n>, digits <n>, spaces <n>, other <n>. Nothing is printed while scanning.

IN   ab 12!
OUT  letters 2
     digits 2
     spaces 1
     other 1

B · Tokenizing C source

B1 · Seven token classes ★★ For every token print <lexeme> --> <class> where class is one of KEYWORD, IDENTIFIER, INTEGER, FLOAT, OPERATOR, PUNCTUATION, STRING. Keywords are int float char double void if else while for return do switch case break continue struct typedef sizeof const static. Punctuation is ( ) { } [ ] ; , .. Skip white space and print nothing for it.

IN   int x = 3.5;
OUT  int --> KEYWORD
     x --> IDENTIFIER
     = --> OPERATOR
     3.5 --> FLOAT
     ; --> PUNCTUATION

B2 · Token stream as pairs ★★ Print one token per line as (<TYPE>, <lexeme>). Types: KW, ID, INT, FLT, OP, PUNCT, STR, CHR. Every non-space character must belong to exactly one token.

IN   x=a+1;
OUT  (ID, x)
     (OP, =)
     (ID, a)
     (OP, +)
     (INT, 1)
     (PUNCT, ;)

B3 · Line and column for every token ★★★ Print line <L> col <C> <lexeme> <TYPE>. Line and column are 1-based; the column is the position of the first character of the lexeme. A tab advances the column by 1.

IN   int x
       y;
OUT  line 1 col 1 int KW
     line 1 col 5 x ID
     line 2 col 3 y ID
     line 2 col 4 ; PUNCT

B4 · Token table with totals ★★ Print one line per token (<lexeme> <TYPE>), then a summary block with these six counters, one per line, in this order: keywords, identifiers, integers, floats, operators, punctuations.

IN   int a=1;
OUT  int KW
     a ID
     = OP
     1 INT
     ; PUNCT
     keywords 1
     identifiers 1
     integers 1
     floats 0
     operators 1
     punctuations 1

B5 · Skip comments while tokenizing ★★ Tokenize into five classes (KW, ID, INT, OP, PUNCT). Both // ... and /* ... */ are consumed and produce neither a token nor output. A // that appears inside a string literal is part of the string, not a comment.

IN   a // x=1
     b /* c */
OUT  a ID
     b ID

B6 · Report unknown characters and keep going ★★ Tokenize into four classes (KW, ID, INT, OP). Any character that cannot start a token must print ERROR line <L> char <c> and scanning must continue on the same line.

IN   a = 1 @ b
OUT  a ID
     = OP
     1 INT
     ERROR line 1 char @
     b ID

B7 · Distinguish declaration from expression ★★★ Print DECL <name> when an identifier is immediately preceded by one of int char float double void, otherwise USE <name>. Keywords and numbers print nothing.

IN   int a; a = b;
OUT  DECL a
     USE a
     USE b

B8 · Two-character operators first ★★ Tokenize operators only, printing OP <text>. The multi-character operators are == != <= >= && || ++ -- += -= *= /= -> << >>. Two adjacent > characters must come out as one >>, never as two tokens.

IN   a>>=b && c!=d
OUT  OP >>
     OP >=
     OP &&
     OP !=

B9 · Split -> from - and > ★★★ For the input p->x--->y print every operator token separately, one per line, in order. Longest match decides how the string is chopped.

IN   p->x--->y
OUT  ->
     --
     ->

B10 · Tokens per line ★★ Print line <L>: <n> for every line, where <n> is the number of tokens on that line (a token is a word, a number, or a single punctuation/operator character). A blank line prints line <L>: 0.

IN   a b

     c
OUT  line 1: 2
     line 2: 0
     line 3: 1

B11 · Normalized re-emission ★★★ Re-print the whole program with exactly one space between tokens and exactly one token per line. A string literal is printed as one token including its quotes.

IN   int   x=1+2;
OUT  int
     x
     =
     1
     +
     2
     ;

B12 · Longest token ★★ Tokenize words and numbers. At the end print longest <token> (<n> chars) for the longest token seen; on a tie the first one wins. With no tokens print longest - (0 chars).

IN   ab cdef gh
OUT  longest cdef (4 chars)

C · Identifiers, keywords and names

C1 · Valid C identifier? ★★ For each line decide whether the entire line is a legal C identifier: first character a letter or _, remaining characters letters, digits or _. Print VALID <text> or INVALID <text>.

IN   _x9
     9x
OUT  VALID _x9
     INVALID 9x

C2 · Keyword, identifier or neither ★★ For each line print KEYWORD <text> if it is one of the 32 C keywords, IDENTIFIER <text> if it is a valid identifier that is not a keyword, INVALID <text> otherwise. Keywords: auto break case char const continue default do double else enum extern float for goto if int long register return short signed sizeof static struct switch typedef union unsigned void volatile while.

IN   int
     count
     2x
OUT  KEYWORD int
     IDENTIFIER count
     INVALID 2x

C3 · Case-insensitive keywords ★★ Recognise the seven keywords int float if else while for return in any letter case and print the canonical lower-case form as KEYWORD <form>. Any other word prints IDENTIFIER <as written>.

IN   INT Total WhIlE
OUT  KEYWORD int
     IDENTIFIER Total
     KEYWORD while

C4 · Leading underscores ★ Print RESERVED <text> for every word that begins with one or two underscores, and NORMAL <text> for every other word. Numbers are ignored.

IN   _foo __bar baz
OUT  RESERVED _foo
     RESERVED __bar
     NORMAL baz

C5 · Longest identifier ★★ Print the identifier with the most characters as longest <text> <n>. On a tie print the one that appeared first. Numbers are ignored.

IN   a bbb cc dddd ee
OUT  longest dddd 4

C6 · Distinct identifiers in first-appearance order ★★★ Print every distinct identifier exactly once, in order of first appearance, as <text> <first line number>.

IN   a b
     a c
OUT  a 1
     b 1
     c 2

C7 · Use before declaration ★★★ A declaration is an identifier directly preceded by the keyword int. When an identifier appears that has not yet been declared, print USE-BEFORE-DECL <n>. When one is declared print DECL <n>. Print nothing for keywords and numbers.

IN   a = 1; int a; a = 2;
OUT  USE-BEFORE-DECL a
     DECL a
     USE a

C8 · Class by first character and length ★★ For every word print <length>-<class> <text>, where class is U if it starts upper-case, L if it starts lower-case, _ if it starts with an underscore.

IN   Alpha beta _x
OUT  5-U Alpha
     4-L beta
     2-_ _x

D · Numbers and numeric literals

D1 · Decimal, octal or hex ★★ Classify every integer literal: 0x or 0X followed by hex digits is HEX, 0 followed by digits is OCTAL, anything else is DECIMAL. Print <class> <text>.

IN   42 017 0x1F
OUT  DECIMAL 42
     OCTAL 017
     HEX 0x1F

D2 · Integer suffixes ★★ Print <value> <suffix-description> for each integer literal, ignoring the suffix when computing the value. Suffixes may be u, U, l, L, ul, ULL in any case combination.

IN   42 42u 42L 42ULL
OUT  42 none
     42 unsigned
     42 long
     42 unsigned-long-long

D3 · Float forms ★★ Recognise four float shapes and print the shape name: 3.14 → DOT, .5 → LEADING-DOT, 1. → TRAILING-DOT, 1e10 and 2.5e-3 → EXPONENT, 1.5f → DOT-FLOAT-SUFFIX.

IN   3.14 .5 1. 1e10 2.5e-3 1.5f
OUT  3.14 DOT
     .5 LEADING-DOT
     1. TRAILING-DOT
     1e10 EXPONENT
     2.5e-3 EXPONENT
     1.5f DOT-FLOAT-SUFFIX

D4 · Malformed numbers, with the reason ★★★ Print INVALID <text> : <reason> for each malformed numeric literal. Reasons must be one of: octal digit 8/9, hex needs a digit, two decimal points, bad suffix, exponent has no digits.

IN   08 0x 1.2.3 42abc 1e
OUT  INVALID 08 : octal digit 8/9
     INVALID 0x : hex needs a digit
     INVALID 1.2.3 : two decimal points
     INVALID 42abc : bad suffix
     INVALID 1e : exponent has no digits

D5 · Value of an integer literal ★★ Print the decimal value of each integer literal, understanding octal and hex notation.

IN   42 052 0x2A
OUT  42
     42
     42

D6 · Value of a character literal ★★★ Print the integer value of each character literal. A plain character is its ASCII code; \n is 10, \t is 9, \0 is 0, \xHH is hexadecimal and \NNN is octal.

IN   'A' '\101' '\x41' '\n'
OUT  65
     65
     65
     10

D7 · Range check against INT_MAX ★★★ Assume INT_MAX is 2147483647. For every decimal integer literal print <text> FITS or <text> OVERFLOW.

IN   100 2147483647 2147483648
OUT  100 FITS
     2147483647 FITS
     2147483648 OVERFLOW

D8 · Digit separators ★★★ Modern C allows a single quote between digits as a separator. Print the value with the separators removed: 1000000. Reject a literal with two adjacent separators or a trailing separator as INVALID <text>.

IN   1'000'000 0x1'F 1''0
OUT  1000000
     31
     INVALID 1''0

D9 · Binary and hex-float literals ★★★★ Print the decimal value of 0b1010 (binary) and of hex-float literals, where 0x1p3 means 1 × 2³ and 0x1.8p1 means 1.5 × 2¹.

IN   0b1010 0x1p3 0x1.8p1
OUT  10
     8
     3

D10 · Digits per number ★ For every integer literal print <text> has <n> digits, counting only the digits (not the 0x prefix, not the suffix).

IN   7 42 0x1F 100
OUT  7 has 1 digits
     42 has 2 digits
     0x1F has 2 digits
     100 has 3 digits

D11 · Sum of all numeric values ★★ Read a text file and print the sum of the values of every integer and every float literal, then integers <n> and floats <n>.

IN   a = 10; b = 2.5; c = 3;
OUT  sum 15.5
     integers 2
     floats 1

D12 · Conversion table ★★★ For every integer literal print the same value written in three ways: <input> dec=<d> oct=<o> hex=<h>, using upper-case hex digits and no leading zeros in the octal form (except for zero itself).

IN   42 8 255
OUT  42 dec=42 oct=52 hex=2A
     8 dec=8 oct=10 hex=8
     255 dec=255 oct=377 hex=FF

E · Strings, characters, escapes and format specifiers

E1 · Strict string-literal validity ★★★ A string is valid when it is opened and closed by " on one line, contains no bare newline, and every escape sequence is one of \n \t \r \\ \" \' \a \b \f \v \?. Print VALID <text> or INVALID <text> : <reason> with reason one of illegal escape, unterminated.

IN   "ok"
     "Test \1"
     "Hello \y"
OUT  VALID "ok"
     INVALID "Test \1" : illegal escape
     INVALID "Hello \y" : illegal escape

E2 · C-exact escapes ★★★ A string literal is valid when it is opened and closed by " on a single line and every escape sequence in it is legal. A legal escape is: a backslash followed by one of n t r a b f v \ ' " ?, or a backslash followed by x and one or more hex digits, or a backslash followed by one to three octal digits. Print VALID <text> or INVALID <text> : <reason>, where the reason is illegal escape or unterminated.

IN   "\x41" "\101" "a\tb" "bad \q"
OUT  VALID "\x41"
     VALID "\101"
     VALID "a\tb"
     INVALID "bad \q" : illegal escape

E3 · Character literal validity ★★★ A character literal must contain exactly one character or exactly one escape sequence between single quotes. Print VALID <text>, or INVALID <text> : <reason> with reason empty, too many characters, or unterminated.

IN   'a' '\n' '' 'ab'
OUT  VALID 'a'
     VALID '\n'
     INVALID '' : empty
     INVALID 'ab' : too many characters

E4 · Format specifiers inside a string literal ★★★★ Inside every string literal, find each % sequence. A %% means a literal percent sign and prints percent %%. Any other % followed by optional flags - + 0 #, an optional width, an optional .precision, and a conversion character from d i u o x X c s f e g p n is a specifier and prints spec <sequence as written>. Print one line per sequence found, in order.

IN   printf("%d items, %.2f%% done\n", n, p);
OUT  spec %d
     spec %.2f
     percent %%

E5 · Validate a printf format string ★★★★ For each line that contains a string literal used as a format, examine every %. If the conversion character is not one of d i u o x X c s f e g p n %, print BAD at position <p>: <sequence> where <p> is the 1-based index of the % inside the string literal (the opening quote is position 1) and stop examining that string. If every % is legal print OK.

IN   "%d %q"
     "%d %s"
OUT  BAD at position 5: %q
     OK

E6 · Count specifiers by conversion character ★★★ For each string literal, count the conversion characters that follow a % (ignoring %%) and print <char> <count> in order of first appearance.

IN   "%d %d %s %f"
OUT  d 2
     s 1
     f 1

E7 · Decode the escapes ★★★★ Print the decoded content of each string literal, showing a decoded tab as <TAB>, a decoded newline as <NL>, a decoded backslash as <BSLASH>, a decoded double quote as <QUOTE> and a decoded octal or hex escape as <CHAR:HH> where HH is the upper-case hex code.

IN   "a\tb" "\x41\101" "q\"q"
OUT  a<TAB>b
     <CHAR:41><CHAR:41>
     q<QUOTE>q

E8 · Length of a string in memory ★★★★ Print length <n> for each string literal, where <n> counts the characters the compiled program would store, i.e. after escape decoding, excluding the quotes and excluding the terminating zero. A tab counts as one, \x41 counts as one, \101 counts as one.

IN   "a\tb\x41\101" "abc" ""
OUT  length 5
     length 3
     length 0

E9 · Wide, UTF and plain literals ★★★ Classify each literal by its prefix: L"..." is WIDE-STRING, u8"..." is UTF8-STRING, u"..." is UTF16-STRING, U"..." is UTF32-STRING, L'.' is WIDE-CHAR, and a literal with no prefix is STRING or CHAR.

IN   L"ab" u8"x" L'a' "p" 'q'
OUT  WIDE-STRING L"ab"
     UTF8-STRING u8"x"
     WIDE-CHAR L'a'
     STRING "p"
     CHAR 'q'

E10 · Adjacent string concatenation ★★★★ Two or more string literals separated only by white space are concatenated by the compiler. For every such run print concatenated <content> (<n> chars) after decoding escapes, and print each run only once.

IN   "ab" "cd"
     "x"  "y"  "z"
OUT  concatenated abcd (4 chars)
     concatenated xyz (3 chars)

E11 · Same character, two quoting styles ★★★ Classify each literal: a "-quoted literal is a STRING, a '-quoted literal is a CHAR, and either may contain the other quote character escaped or bare (a ' inside "..." is legal and needs no escape). Print the class and, for a char literal, its single character.

IN   "it's" '"' "a\"b"
OUT  STRING "it's"
     CHAR '"' contains "
     STRING "a\"b"

E12 · Comment-looking text inside a string ★★★★ For each line determine whether a // or /* inside a string literal was incorrectly taken for a comment, and print string: <text> followed by comment: <text or NONE> for the real comment that follows the string.

IN   s = "a//b"; // real
     t = "x/*y*/"; 
     u = "q"; /* c */
OUT  string: "a//b" comment: // real
     string: "x/*y*/" comment: NONE
     string: "q" comment: /* c */

E13 · Unterminated string, with its line ★★★ Print unterminated string at line <L> for every string literal that is opened and not closed on the same line, and then continue scanning from the next line. Print ok <n> at the end, where <n> is the number of properly closed strings.

IN   "ok" "bad
     "fine"
OUT  unterminated string at line 1
     ok 2

E14 · Escape a raw string back into C form ★★★★ For every line of input, print the same text as a C string literal: enclosed in double quotes, with backslash written as \\, double quote as \", tab as \t, carriage return as \r, and every other non-printable character as \xHH.

IN   a  b
     c"d
OUT  "a\tb"
     "c\"d"

E15 · Count strings, chars and characters ★★ Print strings <n>, chars <n>, string-chars <total decoded characters in all strings>, char-chars <total decoded characters in all char literals>.

IN   "ab" 'x' "c\td"
OUT  strings 2
     chars 1
     string-chars 5
     char-chars 1

E16 · The quote inside the string ★★★★ Print content <decoded content> and length <n> for each string literal, correctly handling the escaped double quote \" so that it neither ends the literal nor counts as two characters.

IN   "a\"b"
OUT  content a"b
     length 3

F · Comments, continuation lines and preprocessing

F1 · Count both comment kinds ★ Print line-comments <n> and block-comments <n>.

F3 · Remove comments but keep the line count ★★ Print the input with comments deleted, so that the number of output lines equals the number of input lines. A line that held only comment text becomes an empty line.

F5 · Comments do not nest ★★★★ /* inside a comment is just text and the comment ends at the first */. Print comment ends at line <L> and then report any */ that appears in code as stray */ at line <L>.

     stray */ at line 1

F6 · A line splice inside a comment ★★★★ A backslash at the end of a line joins it to the next line before lexing, so a // comment containing a trailing backslash continues onto the next line. Print comment spans lines <a>-<b> and code starts at line <c>.

IN   // first \
     still comment
     int x;
OUT  comment spans lines 1-2
     code starts at line 3

F7 · Report include directives ★★ For every #include print INCLUDE system <name> when the header is written in angle brackets and INCLUDE local <name> when it is written in double quotes.

IN   #include <stdio.h>

OUT  INCLUDE system stdio.h
     INCLUDE local my.h

F8 · Object-like or function-like macro ★★★ For every #define print OBJECT <name> if the name is not followed by ( and FUNCTION <name> <n> if it is, where <n> is the number of parameters.

IN   #define N 10
     #define SQ(x) ((x)*(x))
     #define ADD(a,b) (a+b)
OUT  OBJECT N
     FUNCTION SQ 1
     FUNCTION ADD 2

F9 · Delete #if 0 blocks ★★★★ Remove every block that starts with #if 0 and ends with the matching #endif, printing the remaining lines unchanged, then removed <n> lines where <n> counts the removed lines including the directives.

IN   a;
     #if 0
     b;
     #endif
     c;
OUT  a;
     c;
     removed 3 lines

F10 · Trigraphs ★★★★ Obsolete C replaces these three-character sequences before anything else: ??= ??/ ??' ??( ??) ??! ??< ??> ??-. Print <trigraph> becomes <char> for each one found.

IN   ??=define A ??< ??
OUT  ??= becomes #
     ??< becomes {
     ??) becomes }

H · Counting, statistics and reports

H1 · Count, words, characters, lines ★ Print characters <n>, words <n>, lines <n>. A word is a maximal run of non-white-space characters; every character including newlines counts.

How to get the most out of this bank

A four-hour sweep that covers the exam's shape. Do these in order; each is standalone, so a mistake in one never blocks the next: A1 → A3 → B1 → B2 → B4 → C2 → C3 → D1 → D5 → E1 → E3 → E4 → E8 → F1 → F2 → G1 → G3 → H1 → H2 → H3 → I1 → I4 → J1 → J4 → J5 → J6 → K1 → K3 → L1 → L2.

The five tasks that separate a good mark from a top mark. E4 (format specifiers inside a string), E8 (length after escape decoding), F5 (comments do not nest), G1 (a+++b), K7 (common subexpression elimination).

Self-marking, one question at a time. 4 marks if it builds first time; 3 if the sample output matches character for character; 2 if the edge case named in the task is handled (empty line, 1/0, 08, '', unterminated literal); 1 if you can explain each rule in your own words. Twelve out of twelve means move on; below eight means come back to that family tomorrow.

The nine faults that cost the most marks, in order of how often they appear: a catch-all written as .* instead of .; the identifier rule placed above the keyword rule; %option noyywrap together with your own yywrap(); a comment on its own line inside the rules section; an action spread onto the next line; counters printed inside the scanning loop instead of after it; atoi used on a token that is not a number; comparing yytext with == instead of strcmp; and forgetting that . never matches a newline, so a \n rule is always needed.
